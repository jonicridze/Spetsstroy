# ССТ — корпоративный сайт, версия 2

Многостраничный сайт ООО «Спецстройтехнологии»: архитектурная типографика, кинематографическая главная, интерактивный металлический знак Three.js с возвратом, трансформации карточек, адаптивная вёрстка и отключение анимации.

## Быстрый запуск

Нужен Node.js 24.14 или новее в ветке 24, npm. Распакуйте архив, откройте терминал в папке проекта:

```sh
npm ci
```

Скопируйте `.env.example` в `.env`. Для локальной работы оставьте APP_ORIGIN=http://localhost:8788.

```sh
npm start
```

Сайт: http://localhost:8788. Управление: http://localhost:8788/admin. Используйте именно адрес APP_ORIGIN: localhost и 127.0.0.1 имеют разные источники для защиты форм.

## Первый администратор

В локальном `.env` временно задайте SST_ADMIN_EMAIL, SST_ADMIN_NAME и свой уникальный SST_ADMIN_PASSWORD не короче 14 символов. Выполните `npm run admin:create`, затем удалите строку пароля из `.env`. Готового пароля в архиве нет. Новых сотрудников создаёт администратор в разделе «Команда». Редактор управляет материалами и медиатекой; настройки, обращения, вложения, пользователи и журнал доступны только администратору. Изменение пользователя завершает его текущие сеансы.

## Управление содержанием

- Проекты, компетенции, технологии, техника, вакансии, новости, документы, материалы для партнёров и заказчиков, закупки, показатели.
- Статусы: черновик, опубликован, архив. Пустые коллекции и закрытые вакансии скрыты на сайте.
- Изображения, видео, документы, галереи с перетаскиванием и кнопками порядка; SEO заголовки и описания. Предпросмотр несохранённых изменений доступен авторизованному автору в течение часа.
- Главная: заголовок, изображение/видео, CTA, видимость и порядок сцен. Контакты, реквизиты, подписи и порядок меню, социальные ссылки.
- Медиатека: загрузка, поиск, повторное использование, архивирование неиспользуемых файлов. Изображения получают WebP 640/1280/2200 px без увеличения оригинала.
- Обращения: контакты, описание, приватные вложения, статусы, внутренние заметки.

В архиве нет выдуманных проектов, достижений, сотрудников и вакансий. Фоновое изображение из бренд-материалов подписано как визуализация, а не выполненный объект. Коллекции следует наполнить реальными данными компании.

## Заявки и почта

Форма сохраняет обращения в SQLite даже без SMTP. До 5 вложений по 8 МБ; общий запрос до 24 МБ. PDF, DOC/DOCX, XLS/XLSX, JPG, PNG, WebP. Вложения доступны только вошедшему администратору.

Для уведомлений задайте SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, SMTP_FROM и NOTIFY_EMAIL в `.env`. Очередь проверяется раз в минуту, до 5 попыток. Без SMTP письма не отправляются. Письмо содержит уведомление и ссылку в админку; вложения не пересылаются. Проверьте доставку на собственном SMTP перед запуском.

## Выкладка на GitHub

1. Создайте пустой репозиторий GitHub. Приватный подходит для передачи разработчику.
2. Распакуйте ZIP. Загрузите содержимое папки, включая скрытые `.github`, `.gitignore`, `.env.example`, исходники и package-lock.json.
3. Не загружайте `.env`, `data`, `backups`, `node_modules`. Они исключены через `.gitignore`.
4. Через Git: `git init`, `git add .`, `git commit -m "SST website v2"`, затем подключите свой репозиторий и отправьте ветку.

**GitHub хранит исходники. GitHub Pages не запускает Node.js, SQLite, админку и обработку заявок.** Для полноценного сайта нужен сервер/VPS или Node.js-хостинг с постоянным диском. Код и статическая демонстрация опубликованы в GitHub. Полноценная серверная версия требует отдельного размещения.

## Рабочий сервер

Установите Node.js 24, выполните `npm ci --omit=dev`. Задайте APP_ORIGIN=https://ваш-домен, NODE_ENV=production, DATA_DIR с постоянным диском. Один экземпляр приложения на одну базу SQLite. Проксируйте HTTPS через Caddy/Nginx на 127.0.0.1:8788; разрешите запросы до 32 МБ. Не открывайте каталог данных веб-сервером. Запускайте через менеджер процессов или Docker Compose. На production HTTPS обязателен. Создайте администратора в том же DATA_DIR, проверьте домен, форму и почту.

### Docker

Задайте production APP_ORIGIN в `.env`, затем `docker compose up -d --build`. База и файлы сохраняются в томе sst-data. Для первого администратора временно заполните SST_ADMIN_* и выполните `docker compose run --rm sst node scripts/create-admin.mjs`. Затем удалите пароль из `.env` и пересоздайте контейнер: `docker compose up -d --force-recreate`. Docker в рамках поставки не запускался.

## Резервные копии

`npm run backup` создаёт папку с копией SQLite, публичными медиа и приватными вложениями. На время копирования приостановите редактирование и приём новых файлов для согласованности с базой. Копии содержат персональные данные: храните вне репозитория с ограниченным доступом. `.env` сохраните отдельно.

Восстановление: остановите сервер, замените содержимое DATA_DIR файлами копии, восстановите `.env`, запустите сервер. Не заменяйте открытую базу. Организационные сроки хранения и удаление обращений утверждает владелец; автоматическое удаление персональных данных не выполняется.

## Проверки

```sh
npm test
npm run build
```

Тесты с отдельной временной базой: доступы, CSRF/Origin, скрытые черновики, приватный предпросмотр, публикация, конфликт редактирования, экранирование HTML, оптимизация медиа, защита используемых файлов, заявки и приватные вложения, архивирование. Build проверяет синтаксис и локальные ресурсы; HTML рендерится сервером, сборщик не требуется.

## Структура

src — сервер, SQLite, авторизация, медиа, уведомления, HTML-шаблоны. dist — CSS, JS и бренд-ресурсы. scripts — создание администратора, проверки, копирование. tests — интеграционные проверки. Данные появляются в DATA_DIR при первом запуске. Сайт запускается через npm start, а не открытием HTML-файла.

## Перед публичным запуском

Наполните разделы подтверждёнными данными, проверьте права на изображения, утвердите текст конфиденциальности и порядок обработки обращений, настройте домен, HTTPS, SMTP и резервные копии. Google Fonts и Google Maps загружаются с внешних сервисов; это отражено на странице конфиденциальности. Аналитика и рекламные трекеры не подключены.

Логотип и материалы принадлежат их правообладателям. Three.js: MIT, лицензия в dist/assets/vendor/THREE-LICENSE.txt. Платные сервисы для локальной работы не требуются.


## GitHub Pages — демонстрация дизайна

Адрес: https://jonicridze.github.io/Spetsstroy/ . Источник Pages: main, корневая папка. Корневые HTML/CSS/JS и assets — статическая демонстрация; src и dist — полноценная серверная версия.

Для обновления демонстрации выполните `node scripts/build-demo.mjs`, скопируйте содержимое pages (включая .nojekyll) в корень и отправьте изменения. Скрипт всегда использует временную пустую базу и три ЯВНО ПОМЕЧЕННЫХ демонстрационных объекта; реальные обращения и данные CMS не экспортируются. Примеры объектов не являются портфолио ССТ. Страница новостей не содержит вымышленных событий. Для замены примеров отредактируйте src/demo-projects.mjs.

Карта Google Maps показывает выбранный объект. Список поддерживает фильтры по региону и этапу и переходы к карточкам. Для одновременного показа собственных маркеров необходим Google Maps JavaScript API и настроенный ключ; текущая версия использует встроенную Google-карту без ключа. В серверной админке у проектов есть поля широты, долготы и этапа. Без доступа к подложке объекты доступны в списке.

Основные страницы: главная, о компании, наши возможности, проекты, новости, контакты, поставщикам. Тексты возможностей описывают обсуждение задач, а не неподтверждённые производственные мощности компании.
